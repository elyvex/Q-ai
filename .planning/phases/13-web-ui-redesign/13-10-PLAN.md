  <files>web/src/lib/tool-result.ts, web/src/lib/tool-result.test.ts, web/src/components/ToolLedger.tsx, web/src/components/ToolLedger.test.tsx, web/src/api/client.ts, web/src/views/RagDebugView.tsx</files>
  <action>
Wire ONE path through every layer the remaining plans will reuse: the RAG debug form, the typed client, the `ToolResult` shape, and a shared ledger component.

In `web/src/lib/tool-result.ts` declare the `ToolResult` contract that `crates/tools/src/lib.rs` serializes: `tool_name: string`, `tool_version: string` (the domain `SemVer` serializes as a `MAJOR.MINOR.PATCH` string, not an object), `query: unknown`, `normalization_rules: string[]`, `edition_id: string | null`, `edition_version: string | null`, `results: unknown`, `canonical_references: string[]`, `analysis_sources: { kind: string; reference: string }[]`, `confidence: unknown`, `warnings: string[]`, `execution_time_ms: number`, `reproducibility` with `checksum` and `query_hash` as `{ algorithm: string; hex: string }` plus `tool_plan: string[]`, `source_versions: Record<string,string>`, `edition_versions: Record<string,string>`, and `research_checksum: { algorithm: string; hex: string }`. Export `ToolResultData` and `ContentHashValue`.

Add four pure helpers, each with a unit test:
- `checksumLabel(hash: { algorithm: string; hex: string } | null | undefined): string` returns the lowercase algorithm name joined to the hex with a colon (`Sha256` plus hex becomes `sha256:<hex>`), and the empty string for a null or undefined argument.
- `rowsOf(results: unknown): Record<string, unknown>[]` returns the array when `results` is an array of plain objects, otherwise an empty array — never throws on a string, number, null, or nested object.
- `deepLinkFor(canonicalReference: string): string | null` converts a pinned reference of the form `quran:<slug>@<version>:<surah>:<ayah>` into `/read/<slug>@<version>/<surah>:<ayah>`, returning null when the string does not match. Latin identifiers stay unmirrored; this is a URL, not Arabic.
- `editionOf(reproducibility: { edition_versions: Record<string,string> }, slug: string): { slug: string; version: string } | null` looks the caller-supplied `slug` up in `edition_versions` and returns it with its version, or null when that slug is absent. It must not take the first entry of the map: a result that carries more than one edition has no single correct answer, so a caller with no explicit slug renders no deep link. Unit-test the empty map, a single-entry map, a multi-entry map where the requested slug is present, and a multi-entry map where it is absent (null).

In `web/src/api/client.ts` widen `runTool` from `Promise<Envelope<unknown>>` to `Promise<Envelope<ToolResultData>>` importing the type from `../lib/tool-result`, and add `ragDebug(project: string, query: string)` and `ragQuery(project: string, query: string)` that both call `runTool('rag.debug' | 'rag.query', { project, query })`. Do not change any other client signature; `ResearchView` passes envelopes to helpers that accept `{ data: unknown }`, so the widening compiles unchanged.

Create `web/src/components/ToolLedger.tsx` — the single renderer for any `ToolResultData`, in the Concordance idiom (hairline rules, mono for references and counts, no cards, no gradients). It renders, in this order: a header line with `tool_name`, `tool_version`, `execution_time_ms` and the `research_checksum` through `checksumLabel`; a warnings block when `warnings` is non-empty; the `canonical_references` as `deepLinkFor` links (plain mono text when the helper returns null); the `results` as a table of `rowsOf` rows with one column per key in the order the first row presents them (fall back to a `<pre>` of the pretty-printed JSON when `rowsOf` is empty but `results` is not null); and a reproducibility footer listing `tool_plan`, each `edition_versions` entry, and the `query_hash` through `checksumLabel`. When `rowsOf` is empty AND `results` is null, render `EmptyState` with the title `the tool returned no rows`. Values are printed as returned — numbers are not reformatted, and an absent field is not printed as zero. Every cell renders as text, never as HTML.

Rewrite `web/src/views/RagDebugView.tsx` to be that one path: a `project` text field defaulting to `default`, a `query` text field, a submit button, `LoadingLine` while in flight, `ErrorNote` carrying the server's `error.code` and `error.summary` when the request fails, and `ToolLedger` on success. Keep `PageHeader` with the eyebrow `Instruments · Observation`, the title `RAG Debug`, and a `chip` in `actions` that reads `read-only`. The lede states that the screen observes retrieval; it does not create projects or import documents.
