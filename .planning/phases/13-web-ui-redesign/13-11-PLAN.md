<objective>
Give the morphology the engine already holds a screen of its own.

`quran.root`, `quran.lemma`, `quran.family` and `quran.morphology` exist and are dispatched over HTTP, and the five `count/*` routes return rule-attributed reports, but no web route reaches any of them. This plan adds `/words` — the real word inspector the reader's standby annotation row has been waiting for — and wires it into all four navigation surfaces.

Purpose: the reader can show an ayah but cannot answer what a word in it is. That answer is already served; only the surface is missing.

Output: a `/words` route, `web/src/lib/words.ts` for input parsing and link derivation, and a view covering morphology, root, lemma, family and the five counts.
</objective>

`web/src/lib/words.ts` exports `parseWordInput(raw: string): WordQuery | null` with `WordQuery` a discriminated union of `{ kind: 'token'; surah: number; ayah: number; position: number }`, `{ kind: 'ayah'; surah: number; ayah: number }` and `{ kind: 'text'; text: string }`. Trim the input first. `surah:ayah:position` parses as a token, `surah:ayah` as an ayah, any other non-empty string (Arabic or Latin) as text, and the empty string returns null. Reject non-positive and non-finite numbers. Export `tokenId(q: { surah: number; ayah: number; position: number }): string` returning `token:<surah>:<ayah>:<position>` — the exact id the backend builds for a family member. Export `familyKindFor(q: WordQuery): 'token' | 'root' | 'lemma'` mapping a token query to `token`, a text query to `root`, and an ayah query to `token`. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser input → tool params | A free-text field becomes a JSON parameter object |
| server rows → DOM | Occurrence, family and count rows become visible text and links |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|-----------|-----------|----------|-------------|-----------------|
| T-13-05 | Tampering | `deepLinkFor` / `editionOf` build `/read/...` links from tool output | medium | mitigate | Build the link only from `edition_versions` returned by the server; when the map is empty, render plain text and say why. Never accept a slug from the input field. |
| T-13-06 | Spoofing | a count displayed without its rules could read as an unfalsifiable number | high | mitigate | The `rules` block renders unconditionally beside every count, including zero counts; the report `checksum` is printed in mono. |
| T-13-07 | Injection | user text passed as a tool parameter | medium | mitigate | Parameters go through `JSON.stringify` in `post()`; values are never concatenated into a URL path except through `encodeURIComponent` in the existing client. |
| T-13-08 | Denial of service | a count or co-occurrence call with a huge window | low | mitigate | The `window` field is parsed as a positive integer and the control stays disabled otherwise; the server also clamps with `window_tokens.max(1)`. |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds no dependency. Any proposed package requires the package-legitimacy gate and a blocking human checkpoint. |
</threat_model>
