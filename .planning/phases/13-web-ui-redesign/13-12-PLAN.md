<objective>
Expose the whole tool surface as one catalogue, with the parity evidence the CLI already produces.

`POST /api/v1/quran/tool/{name}` dispatches every callable tool through the same registry the CLI uses, so a UI run and a CLI run of the same params return the same `research_checksum`. The web app has no screen that says so. This plan adds `/tools`: a catalogue of the callable tools, a typed form per tool, the shared result ledger, and a surface control that prints the equivalent CLI command and HTTP request for the exact params that were run.

Purpose: a researcher should be able to see the tool's identity, its parameters, its checksum, and the two other ways to invoke it, without leaving the browser.

Output: `web/src/lib/tools.ts` (the catalogue and its three derivations), a `/tools` route wired into all four navigation surfaces, and a view that runs any callable tool and shows the denied ones with their policy code.
</objective>

  <action>
Wire ONE tool end-to-end through the catalogue, the form, the dispatcher and the surface control, then let the catalogue carry the rest in the next task.

`web/src/lib/tools.ts` exports the catalogue types and three derivations:
- `ToolField` = `{ key: string; label: string; kind: 'text' | 'number' | 'json' | 'bool'; required: boolean; placeholder?: string; hint?: string }`.
- `ToolSpec` = `{ name: string; label: string; domain: 'quran' | 'graph' | 'hadith' | 'tafsir' | 'scripture' | 'isnad' | 'rag'; summary: string; fields: ToolField[] }`.
- `TOOLS: ToolSpec[]` — in this task seed it with `quran.get_ayah` only, whose fields are `reference` (text, required), `translations` (json, optional, hint `array of translation slugs`), `glosses` (bool, optional) and `tokens` (bool, optional).
- `DENIED: { name: string; code: string; reason: string }[]` — seed with one entry so the shape is fixed.
- `paramsJson(spec: ToolSpec, values: Record<string, string>): Record<string, unknown>` builds the parameter object: skip a field whose value is the empty string; coerce `number` with `Number()` and reject a non-finite result; parse `json` with `JSON.parse` and reject a parse failure; map `bool` from `'true'`/`'false'`; always include a required field, throwing `{ field: key }` when it is missing. Throw a typed `ToolParamError` carrying the offending field key and a human message — never a bare `Error`.
- `cliCommand(name: string, params: Record<string, unknown>): string` returns `qai quran tool <name> --params '<json>' --json` where `<json>` is `JSON.stringify(params)` with every embedded single quote escaped as the shell sequence quote-backslash-quote-quote. The `--json` flag is global on the CLI.
- `httpRequest(name: string, params: Record<string, unknown>): { method: 'POST'; path: string; body: string }` returns `POST` against `/api/v1/quran/tool/<name>` with the pretty-printed body.

Route wiring — the same four surfaces as the previous plan: add `{ path: '/tools', label: 'Research Tools', crumb: 'Research Tools' }` to `ROUTES`; add the same entry to `DIRECTORY` in `router.tsx`; add `else if (path === '/tools') { content = <ToolsView /> }` to the route switch; append `'/tools'` to the Research entry's `also` array in `NAV`; add `{ name: 'Research Tools', href: '/tools', icon: Terminal }` to `NAVIGATION` in the command menu; add a `/tools` case to `web/src/router.test.tsx` asserting presence in `ROUTES`, `NAVIGATION` and `DIRECTORY`, and that `isActive('/research', '/tools', ['/words', '/tools'])` is true.

`web/src/views/ToolsView.tsx`: `PageHeader` with eyebrow `Instruments · Tools`, title `Research Tools`, and a lede stating that every tool here is dispatched through the same registry as the CLI, so the checksum is identical across surfaces. A left column lists the catalogue grouped by `domain`; the selected tool's form renders in the main column. A `surface` three-way `seg` control selects `ui`, `cli` or `http`. In `ui` the form's `Run` button calls `runTool(spec.name, params)` and renders `ToolLedger`; in `cli` and `http` the form is replaced by the derived invocation in a mono `<pre>` with a copy button, and a line states that the checksum shown on the `ui` surface is the one the CLI returns for the same `--json` invocation. Copy uses `navigator.clipboard.writeText` and surfaces a failure message when the clipboard is unavailable — never a silent no-op.
