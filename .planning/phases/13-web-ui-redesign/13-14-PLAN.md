<objective>
Give citations a workbench and the isnad graph a read-only reading room.

`GET /api/v1/quran/citations/{id}` re-verifies a stored citation server-side and returns a verdict, a corpus `text_hash`, a URN and a deep link, but the only surface is the inline panel under a reader page. `isnad.trace`, `isnad.narrator` and `isnad.rijal` have no surface at all. This plan adds `/citations` — verdict, hash, URN, re-verify, and a labelled local tamper simulation with a byte-exact diff — and `/isnad` — read-only trace, narrator and rijal over the shared ledger, with the denied identity mutations stated as such.

Purpose: the product's central promise is that a quotation either verifies or fails loudly. A researcher needs a screen that shows the verification evidence and demonstrates what a changed character does to it, without ever implying the browser can forge or repair a verdict.

Output: `web/src/lib/byte-diff.ts`, `/citations`, `/isnad`, and four navigation surfaces kept in agreement.
</objective>

`web/src/lib/byte-diff.ts` exports `ByteDiff` = `{ equal: boolean; expectedLength: number; actualLength: number; firstMismatch: { index: number; expected: string; actual: string } | null }` plus `byteDiff(expected: string, actual: string): ByteDiff`, `codePointLabel(value: string): string` and `describeDiff(diff: ByteDiff): string`. Compare by Unicode code point using `Array.from`, never by UTF-16 index, so Arabic with combining marks is compared as the reader sees it. `expectedLength` and `actualLength` are code-point counts. When the shared prefix matches and the lengths differ, `firstMismatch.index` is the shorter length and the missing side is the empty string. `codePointLabel` returns `U+` followed by the code point in uppercase hex padded to four digits, or the literal `end of text` for the empty string. `describeDiff` returns `byte-identical · <n> code points` when equal and `first difference at code point <index>: expected <label>, found <label>` otherwise.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser copy → diff panel | Locally edited text is compared against fetched canonical text |
| server verdict → screen | The only authority on whether a quotation verifies |
| browser → isnad tool route | Read tools are allowed; identity mutations are refused |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|-----------|-----------|----------|-------------|-----------------|
| T-13-17 | Spoofing | an edited local copy presented as a verified quotation | critical | mitigate | The verdict panel renders only server data and stays visually separate from the simulator; the simulator block states it cannot recompute `text_hash` and cannot change the verdict, and the test asserts the verdict text is unchanged after an edit. |
| T-13-18 | Tampering | client-side recomputation of `text_hash` to "fix" a mismatch | high | mitigate | No hashing code is written in the browser; the only hash displayed is the string the endpoint returned, labelled as the server's corpus fingerprint. |
| T-13-19 | Elevation of privilege | isnad identity mutations reached from the browser | high | mitigate | The denied list has no form and no control; the server independently refuses these names with `QAI-ISNAD-0326` unless the operator opts in. |
| T-13-20 | Information disclosure | citation ids and narrator ids in the URL | low | accept | Ids are opaque local identifiers; the route is loopback-only and the payload carries no credential. |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds no dependency — the diff is a code-point comparison, not a diff library. Any proposed package requires the package-legitimacy gate and a blocking human checkpoint. |
</threat_model>
