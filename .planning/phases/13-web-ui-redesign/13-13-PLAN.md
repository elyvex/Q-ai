<objective>
Make the reading room adjustable without touching the text.

The reader currently offers three translation modes and three inspector modes and nothing else: one fixed Arabic size, one arrangement, no way to mark a verse, and no way to ask what else the corpus holds about the verse in front of you. This plan adds a three-step size control, three canonical/translation layouts, localStorage-backed display prefs and bookmarks, and an on-demand related-text lookup that is labelled for exactly what it is.

Purpose: a research reader needs to set the page up once and keep it, mark the verses that matter, and get from a verse to the corpus without losing the page.

Output: `web/src/lib/reader-storage.ts`, `web/src/lib/related.ts`, a size-aware `AyahColumn`, a layout-aware `ReadingView`, and tests that pin the Arabic invariants in every layout.
</objective>

  <action>
Wire the whole display path once: control, state, storage, layout, and the canonical element.

`web/src/lib/reader-storage.ts` exports `ReaderPrefs` = `{ size: 'sm' | 'md' | 'lg'; layout: 'stacked' | 'side-by-side' | 'interlinear'; translationMode: 'inline' | 'side-by-side' | 'side-panel'; inspectorMode: 'popover' | 'panel' | 'pin' }` with `DEFAULT_PREFS` (`md`, `stacked`, `inline`, `popover`). Export `loadPrefs(storage: Pick<Storage, 'getItem'>): ReaderPrefs` and `savePrefs(storage: Pick<Storage, 'setItem'>, prefs: ReaderPrefs): void` using the key `qai.reader.prefs.v1`. `loadPrefs` must never throw: a missing key, invalid JSON, a non-object, or a value outside the allowed set falls back to the default for that single field while keeping the valid siblings. Accept the storage object as an argument so the test needs no global.

`AyahColumn` gains an optional `size?: 'sm' | 'md' | 'lg'` prop defaulting to `'md'`, mapped to three explicit class strings — `sm` is `text-[1.75rem] leading-[2.15]`, `md` is `text-[2rem] leading-[2.15]`, `lg` is `text-[2.25rem] leading-[2.2]` — and sets `data-ayah-size={size}` on the `<p>`. Do not add `sm:` breakpoint variants: all three values must stay inside the UI-SPEC §4 display band of 1.75 → 2.25 rem at every viewport, and every leading must stay inside the §15 Amiri band of 2.15 → 2.2. Those three pairs are the complete selectable set, so no reachable control can push the Arabic outside either band. Do not add a CSS custom property and do not touch `layers.css`: the class swap avoids a specificity fight with `.ayah-canonical`. The prop contract stays presentational only; the canonical slot still accepts no translation or annotation text.

`DisplayModeControl` gains a third `ModeRow` labelled `layout` with the three layout values, and gains an optional `disabledReason?: string` on `ModeRow` so the `translation` row can render `aria-disabled="true"`, keep its buttons focusable, and show the reason as a `title` plus a visible margin line. When `layout` is not `stacked` the translation row is disabled with the reason `the layout owns the translation frame — switch to Stacked to choose how translations collapse`; clicking it does nothing.

`ReadingView` reads `loadPrefs` once on mount (guarded for a missing `localStorage`), keeps the four values in state, and writes the whole object back through `savePrefs` whenever any of them changes. Put `data-ayah-size` and `data-ayah-layout` on the outermost element alongside the existing `data-translation-mode` and `data-inspector-mode`, and pass `size` to every `AyahColumn`.

Three layout branches inside each verse article:
- `stacked` renders exactly what ships today.
- `side-by-side` renders a `md:grid-cols-2` grid whose first cell is the canonical block and whose second cell holds every translation; the canonical cell comes first in document order at every width so the reading order never depends on the grid, and the translation cell carries `dir="ltr"`.
- `interlinear` renders the canonical block with reduced vertical padding, then one `data-interlinear` line per translation: a hairline top border, the translator label inline in mono uppercase, and the text below, all `dir="ltr"`.

Add the size stepper to the margin beside the existing `Display` block: three `seg` buttons labelled `A`, `A`, `A` at increasing type sizes with `aria-label` values `small`, `medium` and `large`, `aria-pressed` on the active one.

Extend the tests. `reader-storage.test.ts`: a missing key yields defaults; a partial object keeps valid fields and repairs invalid ones; a non-object yields defaults; a round trip through a fake storage returns what was saved. `AyahColumn.test.tsx`: the default size renders the `md` classes (`text-[2rem]`, `leading-[2.15]`) and `data-ayah-size="md"`; `sm` renders `text-[1.75rem] leading-[2.15]`, `md` renders `text-[2rem] leading-[2.15]`, `lg` renders `text-[2.25rem] leading-[2.2]`, each pinned literally in the assertion; `dir="rtl"`, `lang="ar"` and the `ayah-canonical` class hold at all three sizes. `DisplayModeControl.test.tsx` (new): the layout row reports the active value; the translation row is disabled with the reason when the layout is not `stacked`. `ReadingView.test.tsx`: each layout produces its distinct marker — the side-by-side grid has two cells with the canonical cell first, interlinear renders one `[data-interlinear]` line per translation, and the Arabic element keeps `dir="rtl"` and the canonical class in all three.

Add the one cross-domain question the reader can actually answer from this surface, and label it precisely.

`web/src/lib/related.ts` exports `seedQuery(arabicText: string, maxChars = 40): string` returning the first `maxChars` Unicode code points of the trimmed text — build it from `Array.from(text)` so a combining mark or a surrogate pair is never split — and `RELATED_NOTE`, the single source of the disclaimer sentence: these are text-search hits seeded by this verse's own wording, not tafsir or hadith commentary attached to the verse.

In `ReadingView`, each verse header gains a `related` button. Pressing it calls `runTool('tafsir.search', { query: seed, limit: 5 })` and `runTool('hadith.search', { query: seed, limit: 5 })` concurrently and renders, inside that verse's article: the exact seed in mono under a `seeded query` label, the tafsir hit count and the hadith hit count, and `RELATED_NOTE`. Count a result by `rowsOf(result.results).length`; when `results` is an object carrying a `hits` array, use that array's length; when neither applies, print `unknown` rather than `0`. A failed call renders its `error.code` and `error.summary` for that domain only, leaving the other domain's count visible.

Keep the control per-verse and on demand: nothing is fetched until the button is pressed, and no count is precomputed for verses the user has not asked about. While in flight the button shows a loading state and is disabled; it is not disabled at rest.

Extend `related.test.ts`: a 60-code-point Arabic string truncates to 40 code points without splitting a surrogate pair; a short string returns itself trimmed; whitespace-only returns the empty string; `RELATED_NOTE` mentions both `tafsir` and `hadith` and the word `seeded`. Extend `ReadingView.test.tsx`: pressing `related` on a verse renders the seeded query, both counts and the note; a stubbed error for `tafsir.search` renders its code while the hadith count still appears; no request is issued before the button is pressed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → rendered reader state | Browser-writable storage feeds layout and bookmark rendering |
| verse text → search query | Canonical Arabic becomes a parameter sent to two tools |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|-----------|-----------|----------|-------------|-----------------|
| T-13-13 | Tampering | `loadPrefs` / `loadBookmarks` read attacker-writable localStorage | medium | mitigate | Validate every field against a closed allow-list and drop malformed entries; a bad value falls back to the default instead of reaching a class name or an href. |
| T-13-14 | Spoofing | a `related` hit count read as commentary on the verse | high | mitigate | `RELATED_NOTE` renders beside every count, the exact seed is printed in mono, and the button is named `related` rather than `tafsir` or `hadith`. |
| T-13-15 | Tampering | bookmark `reference` used to build a deep link | medium | mitigate | Build the href only through `deepLinkFor`'s pinned-reference parse; a non-matching reference renders as plain text with no link. |
| T-13-16 | Information disclosure | bookmarks written to localStorage | low | accept | Bookmarks hold public canonical references and a timestamp; the margin note states they are browser-local and outside the corpus and audit trail. |
| T-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds no dependency. Any proposed package requires the package-legitimacy gate and a blocking human checkpoint. |
</threat_model>
