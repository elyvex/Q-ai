# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend surfaces (Web GUI, TUI, CLI). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: RAG project lifecycle (create/import/query/debug), hybrid retrieval results, routing transparency (`route_decision`), reproducible result sets, source activation/deactivation/tombstoning. Cross-surface parity: CLI (`CommandOutput { human, json }`), TUI (ratatui screens), Web (React + CSS tokens). Typed tool results (`ToolResult`) with `research_checksum` and `route_decision` on every envelope. No shadcn — plain React + CSS tokens (web), ratatui (TUI), plain-text (CLI).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Rust CLI + ratatui TUI + React/Vite Web; shadcn gate not applicable) |
| Preset | not applicable |
| Component library | none — CLI plain-text renderer (`CommandOutput { human, json }`); TUI ratatui widgets (Block, Table, List, Paragraph); Web plain React components + CSS tokens (no component library) |
| Icon library | none (text-only CLI/TUI; Web uses text labels only, no icon-only actions) |
| Font | CLI/TUI: terminal monospace (inherited); Web: `system-ui, 'Segoe UI', Roboto, sans-serif` (from `web/src/index.css`); Arabic corpus text (if surfaced) uses `--layer-font-arabic` |

Focal point per surface (summary first, detail below, truncation always inline on the summary line, never hidden): project create/import → the `created <name> at <path>` / `imported N (skipped M)` line; query → the `<N> hit(s)` count line then ranked hits; debug → the `route: <router>` summary line then the decision trace; TUI → the table header row then rows; Web → the section heading then the list. No icon-only actions; every status is a word (`active`, `deactivated`, `tombstoned`, `pending`, `truncated`), never color or glyph alone.

## Spacing Scale

Declared values (must be multiples of 4). Web uses the px scale; CLI/TUI use character/cell grids.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps between id and score (Web) |
| sm | 8px | Compact row spacing, badge padding (Web) |
| md | 16px | Default element spacing, section padding (Web) |
| lg | 24px | Card/panel padding, section breaks (Web) |
| xl | 32px | Layout gaps between result list and route panel (Web) |
| 2xl | 48px | Major section breaks (Web) |
| 3xl | 64px | Page-level spacing (Web) |

Exceptions: none (Web). CLI/TUI spacing is cell-based (see terminal grid below).

Normative terminal grid (character columns/cells, not px — literal output bytes pinned by trycmd snapshots and ratatui constraints):

| Rule | Value | Where |
|------|-------|-------|
| Summary line | column 0, single line | every read verb (`rag query …`, `rag debug …`, `rag create …`) |
| List indent | 2 spaces | result/hit rows and trace lines (`  1. <ref> — <score>`); source rows (`  <source> (active)`) |
| Remedy indent | 6 spaces | error `      remedy: …` / `      next: …` lines (CLI) |
| Truncation marker | inline ` (truncated)` + `\nincomplete: <reason>` verbatim | every partial result, human + JSON output |
| Row rhythm | single-spaced, one finding per line | all CLI human output |
| TUI table | Block borders, columns: rank 4, ref Min(10), score 8, source 12 (mirrors `render_search`/`render_graph_nav`) | query result screen |
| TUI debug | Block title `RAG debug`, Paragraph rows indented 2 cells | debug screen (replaces unavailable stub) |
| Web grid | CSS: `gap: var(--space-md)` (16px) between cards; results stacked with 8px gap; route panel separated by 32px | query/debug views |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 18px (Web) / terminal default (CLI/TUI) | regular (400) | 1.45 (Web) / 1.0 (CLI/TUI single-spaced rows) |
| Label | 14px (Web) / terminal default | regular (400) | 1.4 (Web) |

4 sizes, 2 weights. Score numbers and checksums render in `--mono` (ui-monospace); never a separate size token. CLI/TUI use terminal defaults only (no custom font).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Web: `#ffffff` (light) / `#16171d` (dark) bg; CLI/TUI: terminal default (zero color codes) | Background, surfaces, all CLI output inherits operator theme |
| Secondary (30%) | Web: `#f1f5f9` (`--layer-translation-bg`) cards/sidebar/nav; TUI: ratatui default block borders | Cards, sidebar, nav, result rows, route panel |
| Accent (10%) | Web: `#aa3bff` (light) / `#c084fc` (dark); CLI: `#a00` truncation only | Specific enumerable set only (see below) |
| Destructive | Web: `#dc2626`; CLI/TUI: red (ratatui `Color::Red`) | Destructive actions only (tombstone confirmation) |

Accent reserved for: (1) truncation banners — `truncated: <reason>` (Web `<p className="graph-truncated">`, TUI yellow Paragraph, CLI inline ` (truncated)`); (2) `pending` source status chips; (3) `uncertain` confidence on computational links; (4) the primary CTA button. Accent is never applied to headings, result ink, or canonical text. Status words carry meaning, not color alone: `active` (default), `deactivated` (muted/secondary), `tombstoned` (destructive red). Provenance layers reuse existing layer tokens (B/C/D) for any corpus text surfaced.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `qai rag query <project> "<query>"` — run a hybrid retrieval query (e.g. `qai rag query myproj "justice in the quran"` → `<N> hit(s)` + ranked results + `route: <router> (checksum <hex>)`). Web button label: `Query`. TUI key: `q`. |
| Project create | `created <name> at <project-dir>` (CLI) / Web toast `Project created.` / TUI `created <name>`. Empty name → usage error. |
| Project import | `imported <N> document(s) (skipped <M>)` (CLI) / Web `Imported N (skipped M).` / TUI same. Zero docs → `imported 0 document(s) (skipped 0)` (zero-count line, never generic). |
| Query result heading | `<N> hit(s)` count line first; then `<rank>. <ref or doc-id> — <score>` rows; final line `route: <router> (checksum <hex>)`. |
| Empty result set | `0 hit(s) for "<query>"` (typed, exit 0) — never a blank panel. Web: `No results for “{query}”.` |
| Empty project (no docs) | `project <name>: 0 document(s)` (zero-count line). |
| Empty active sources | `sources for <project>: 0 active` (zero-count line). |
| Debug heading | `route: <router>` then indented trace: `tools: <t1>, <t2>`; `sources: <s1>, <s2>`; `candidates: <N>`; `merged (RRF): <N>`; `reranked: <N>`; `final: <N>`; `checksum: <hex>`; `excluded (non-active): <N>` (only if >0). |
| Truncated result set | `… (truncated)` + `incomplete: <reason>` verbatim on the count line (CLI); Web `truncated: {reason}` banner; TUI yellow footer. Partial results never rendered as absence or negative claims. |
| Status words | Source status: `active`, `deactivated`, `tombstoned`. Result labels: `hit`, `candidate`, `merged`, `reranked`, `final`. |
| Error state | `[QAI-RAG-NNNN] <detail>` + `Remedy: <fix>` + `Next: qai rag … --help` (code + remedy + next command always together, never a bare message). Web: `<p role="alert">{summary}</p>` with remedy text. TUI: red Paragraph. Examples: unknown project → `NOT_FOUND`; bad config → `VALIDATION`; missing embedding provider → `GENERIC`. |
| Destructive confirmation | `rag source tombstone <project> <source>` requires `--yes` or terminal `Type APPROVE to tombstone \`<source>\``; refusal renders `refusing to tombstone without --yes` (non-terminal) or `not approved`. Success renders `tombstoned <source> (audit #<seq>)`. Web: modal dialog `Tombstone {source}?` + `Confirm tombstone` + `Cancel`; TUI: confirmation Paragraph with `APPROVE` prompt. |
| Reproducibility line | `checksum: <hex>` (full) in debug; `route: <router> (checksum <hex>)` (short) in query. Same config + corpus + query → identical checksum. |

| zero-one-many | all counts | ✅ covered | Invariant `(s)` suffix at every count (`1 hit(s)`, `2 candidate(s)`); no singular/plural branching |
| long-text | query strings / doc ids | ✅ covered | Query echoed verbatim (quoted) in empty state; ids never clipped; Web wraps within row |
| long-text | route decision fields | ✅ covered | Tool/source names wrap in panel; checksums render in mono and never wrap mid-token |

## Cross-Surface Parity

| Surface | Create | Import | Query | Debug | Source mgmt |
|---------|--------|--------|-------|-------|-------------|
| CLI | `qai rag create <name>` | `qai rag import <project> <docs>` | `qai rag query <project> "…"` | `qai rag debug <project> "…"` | `qai rag source {activate,deactivate,tombstone}` |
| TUI | (via command palette / jobs) | (via jobs progress) | rag-debug screen reused with query input | rag-debug screen (route trace) | ops screen status rows |
| Web | project form (React) | import dropzone/form (React) | query form + results (React) | `/rag-debug` route (RagDebugView upgraded) | source list with status badges (React) |
| Typed tools | `rag.create`, `rag.import` | `rag.import` | `rag.query` | `rag.debug` | `rag.source_activate`, `rag.source_deactivate`, `rag.source_tombstone` via `/api/v1/quran/tool/{name}` |

All surfaces consume the same `ToolResult` envelopes with `research_checksum` and `route_decision`; no surface re-derives data. Route decision fields and truncation state are copied verbatim from the envelope. Reproducibility checksum is computed server-side and never recomputed client-side.
