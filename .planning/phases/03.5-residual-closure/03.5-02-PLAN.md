<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| absent dataset → numeric report | Missing input crosses into a number a reader might trust |
| operator → confirmed repair | Only the explicit repair path may mutate derived state |
| sampled pass → full pass | A partial scan crosses into a report that reads as exhaustive |
| scheduled job → audit chain | An unattended run writes durable records |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3.5-06 | Tampering | counting surface | high | mitigate | Thin wrappers over one service per operation, so CLI and HTTP cannot return different numbers; parity proven by the route/verb count verify |
| T-3.5-07 | Repudiation | unavailable-dataset path | high | mitigate | Typed QAI-MORPH-0004 / QAI-LEX-0004 on both surfaces; a test asserts neither an empty list nor an empty 200 is reachable |
| T-3.5-08 | Tampering | index verify job | high | mitigate | One rolled-back UnitOfWork, no write method, before/after byte-identity test; the job never holds a mutation lock |
| T-3.5-09 | Repudiation | sampled report | medium | mitigate | Sample size and rate are in the report payload; a test asserts a sampled pass is distinguishable from an exhaustive one |
| T-3.5-10 | Denial of service | cold-rebuild budget | medium | mitigate | The rebuild is bounded by the job lease and checkpointing; the budget row makes an over-run visible rather than silent |
| T-3.5-SC | Tampering | package installs | low | accept | Zero new dependencies; existing crates only |
</threat_model>
