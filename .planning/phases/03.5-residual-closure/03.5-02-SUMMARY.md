## Decisions Made

- **CLI/HTTP parity via thin wrappers:** All counting routes in `quran_lexicon_api.rs` are thin wrappers over the same service functions the CLI calls, so the two surfaces cannot drift (D-10 precedent).
- **Read-only job by construction:** IndexVerifyHandler opens a UnitOfWork that always rolls back, calls no write method, and takes no mutation lock (D-3.5-09).
- **1% sample with metadata:** The verification report states its sample size and sample rate so a sampled pass is never readable as an exhaustive pass.
- **Enqueue-only CLI boundary:** `qai quran index verify-job` enqueues the job and returns the job id; it never blocks on completion (D-13 precedent).
