<objective>
Give `subgraph`, `pattern` and `root-family` first-class graph workspaces instead of leaving them as untyped JSON fields in the generic tool runner — with export, per-edge provenance, and reader links.

Purpose: R8 names exactly three tools, and all three already answer over `POST /api/v1/quran/tool/{name}` with a full `ToolResult` (identity, reproducibility, `research_checksum`, `canonical_references`, warnings), so the typed view can reuse `runTool` and `ToolLedger` instead of inventing a client. The graph *route* family (`/quran/graph/subgraph`) returns a different, ledger-less shape; the tool route is the one that gives a checksum and linkable references, which is what the acceptance criteria require. The export requirement (JSON/DOT/SVG) is client-side serialisation of the already-returned graph — `quran graph export` is a CLI file write and needs no HTTP route.
Output: `web/src/lib/graph-export.ts` plus a tabbed `GraphView`.

**Code facts verified at HEAD (do not re-derive):**
- Tool parameters (`crates/tool-registry/src/lib.rs:721-770`): `GraphSubgraphParams{seeds: Vec<String>, edge_types?: Vec<String>, direction?: String, budgets}`; `GraphPatternParams{seeds, steps: Vec<{edge, node_kind?}>, budgets}`; `GraphRootFamilyParams{root, limit?}`. Steps are validated `1..=8`.
- `EDGE_VOCABULARY` is 21 upper-case predicates (`CONTAINS, NEXT, MENTIONS_CONCEPT, REFERS_TO, MENTIONS, CITES, CONTRASTS_WITH, PARALLELS, EXPLAINS, TRANSLATES, RELATED_TO, SUPPORTED_BY, DISPUTED_BY, HAS_LEMMA, HAS_ROOT, HAS_STEM, DERIVED_FROM, SAME_ROOT_AS, SAME_LEMMA_AS, TRANSMITS, NARRATES`). `parse_node_kind` accepts `edition|surah|ayah|token|division|root|lemma|concept|entity|annotation`.
- `results` for subgraph/pattern is `SubgraphOutput`/`PatternOutput` = `{nodes:[{stable_id,kind,attrs}], edges:[{src,edge,dst,assertion_id?,attrs}], truncated, incomplete_reason?, explanation}`. Root family is `{root, dataset, ayahs:[{surah,ayah,position}], limit, duration_ms}`.
- `backend_graph_root_family` builds `canonical_references` as `quran:<edition_slug>@<edition_version>:<surah>:<ayah>` — that is what makes `deepLinkFor` work for family rows. Subgraph/pattern references come from `explanation_references`.
- `lib/tools.ts` currently advertises `[{"edge":"contains","direction":"out"}]` for `quran.graph_pattern` and `["quran:2:1"]` for seeds — both wrong (`node_kind`, and node ids are `ayah:2:1`). `ToolsView` renders these hints verbatim, so the correction is a user-facing fix.
- `GraphView` is called from `router.tsx` as `<GraphView lines={[]} truncated={false} />`; its three existing tests assert "Knowledge Graph", the empty sentence, verbatim lines, and `truncated: budget exceeded`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/quran/tool/quran.graph_* | operator-typed seeds, edges, node kinds, root and limit cross here |
| graph payload → rendered tables and downloads | node/edge labels and provenance become DOM text and file content |
| rendered graph → reader navigation | a canonical reference becomes a URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-43 | Tampering | SVG/DOT export | medium | mitigate | Labels are escaped before interpolation; only `stable_id`, `kind`, `src`, `edge`, `dst` and escaped labels are emitted; no HTML injection path and no `dangerouslySetInnerHTML` |
| T-14-44 | Denial of service | pattern step editor / seeds | medium | mitigate | Steps hard-capped at 8 (the server's own bound) and seeds at 8; one request per explicit run, no retry loop |
| T-14-45 | Spoofing | provenance columns | high | mitigate | `assertion_id` and `attrs` print as served; an absent assertion renders the literal structural sentence, so no reader can mistake a structural edge for an attributed claim |
| T-14-46 | Info disclosure | exports | low | accept | An export contains only data the browser already received; no new request is made to build it |
| T-14-47 | Open redirect | root-family reader links | low | mitigate | Links are built only from server `canonical_references` through `deepLinkFor`, which accepts the `quran:<slug>@<version>:<s:a>` grammar; no raw payload string is used as an href |
| T-14-SC | Tampering | web dependencies | low | accept | No package added; `npm run build` + `layer_separation` gate the change |
</threat_model>
