<objective>
Give phase 14 its proof: a Playwright suite that drives the real web application against a real `qai serve`, plus the CI job that runs it on a clean runner.

Purpose: R12 is the difference between "the views compile" and "the product works". Every earlier plan in this phase proves its own layer with Rust or jsdom tests; this plan proves the seams between them — SPA over a seeded engine, typed envelopes rendered as working interfaces, deny-by-default visible rather than assumed. The suite is also the phase's regression net for R14's per-route upgrades and R13's accessibility work.

Output: `web/playwright.config.ts`, the `web/e2e/` harness (seed, setup, teardown, fixtures, route list) and eleven specs covering the thirteen legacy routes and the four new surfaces, a route-parity vitest guard, the `.github/workflows/ci.yml` `web` job, gitignore entries for artifacts, and `docs/06-progress/phase-14-e2e.md`.

**Engine contract (grounded in the repo, do not re-derive):** `qai` has only the global `--data-dir` override and `serve --bind`; the DB path resolves to `${app.data_dir}/qai.db` and the objects root under the same dir, so one `--data-dir <tmp>` isolates a whole run. The SPA is embedded into the binary at Rust compile time (`crates/server/src/webassets.rs`), so `web/dist` must exist and be older than the binary. `serve` refuses a bind that is not loopback.

**Fixture contract:** `fixtures/quran/test-edition-min` is the committed corpus (5 surahs, 14 ayahs, `synthetic: true`, `ayahs.csv` + `manifest.json`). There is no committed hadith, tafsir or scripture corpus; those specs therefore assert the routes' typed empty/error states against the live engine — that is the honest E2E assertion for them and is recorded as such in the evidence doc.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Playwright (Node) → `qai` process | the only place a process is spawned; argv and env are built from literals plus a temp path |
| browser → engineered SPA/API | untrusted interaction over loopback; the page itself has no process access |
| test run → git / CI artifacts | traces and screenshots may contain local paths and rendered data |
| `npm ci` → the runner | devDependency supply chain, already locked in `web/package-lock.json` |
