<objective>
Turn the ten already-served REST endpoints that no view reaches into browsable data surfaces, without adding a route and without touching canonical text.

Purpose: R7 is a pure UI gap (`14-COVERAGE.md` A2/A3/A4/A5/A7/A9/A10 and Q1). Two edges drive the design: `verse_links_handler` returns `[]` for both "no links" and "no link service", so absence must be reported as absence-of-served-links; and the normalization preview must stay visually separate from canonical text because `13-UI-SPEC.md` forbids altering or repainting canonical text.
Output: `web/src/api/reference.ts` and the reader/Words/Explorer surfaces listed in `must_haves.artifacts`.
</objective>

**Code facts verified at HEAD (do not re-derive):**
- Routes and shapes (`crates/server/src/api.rs`): `GET /api/v1/meta` → `{name, version}`; `GET /api/v1/quran/editions?status=&language=` → array of edition JSON objects (fields include `status`, `language`, `text_hash`, `statistics`); `GET /api/v1/quran/editions/{slug}`; `GET /api/v1/quran/surahs?edition=` → `[{number, name_arabic, name_transliteration, ayah_count}]`; `GET /api/v1/quran/surahs/{number}?edition=` → `{number, name_arabic, ayahs: [arabic strings]}`; `GET /api/v1/quran/context/{reference}?edition=&before=&after=&boundary=surah|juz|ruku|page|none&max_ayahs=` → the `quran.get_context` tool `results`; `GET /api/v1/quran/divisions/{kind}/{number}?edition=` → `[{canonical_reference, arabic_text}]`; `GET /api/v1/quran/tokens/{reference}?edition=` → `[{position, surface, char_start, char_end, byte_start, byte_end, is_pause_mark}]`; `POST /api/v1/quran/normalization/preview` body `{text, profile}` **or** `{text, rules}` (never both — the server errors) → `{input, profile, output, trace, steps}`; `GET /api/v1/quran/normalization/profiles` → `{profiles: [...]}`; `GET /api/v1/verse/{surah}/{ayah}/links?include_uncertain=` → `[VerseLink]` or `[]`.
- `verse_links_handler` returns `[]` with 200 when `state.verse_links` is `None`; there is no "unconfigured" signal in the envelope.
- `divisions_handler` and `tokens_handler` set `meta.canonical_reference` only for divisions (first view); tokens set no reference.
- `ReadingView` receives `ayahs` as a prop from `router.tsx` and renders canonical text itself; it must not become a second fetcher of ayah bodies. New blocks fetch only context/divisions/links/editions/surahs and render their own rows.
- `router.tsx` parses `/read/<edition>/<surah>:<ayah>` but `fetchAyahs` sends only `<surah>:<ayah>`; the edition segment is navigation metadata. Any deep link built here must use the same shape `lib/tool-result.deepLinkFor` produces (`/read/<slug>@<version>/<surah>:<ayah>`) or the plain `/read/active/<surah>:<ayah>` already accepted by `DEEP_LINK`.
- `WordsView` already has a token-reference input and `parseWordInput`/`tokenId` in `lib/words.ts`; reuse that parsing for the token inspector rather than a second parser.
- `client.ts` exports `apiGet`/`apiPost` as of 14-07.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/quran/{editions,surahs,context,divisions,tokens,normalization} | operator-typed reference, profile and free text cross here |
| browser → /api/v1/verse/{s}/{a}/links | path parameters address a verse |
| normalization preview → rendered page | transformed text is displayed beside canonical text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-38 | Tampering | normalization preview vs canonical text | high | mitigate | The preview lives in its own section with a `preview` kicker and a note; no preview value is passed to `ReadingView`, stored, or used to decorate an ayah; the panel performs no write call because none exists |
| T-14-39 | Spoofing | verse-link absence | medium | mitigate | `[]` renders "no links are served", never "there are no links"; the empty sentence names the server as the source of the empty result |
| T-14-40 | Denial of service | surah detail / tokens | medium | mitigate | Requests are one-shot per explicit action (no polling, no prefetch fan-out); context `before`/`after` are clamped in the form and `max_ayahs` stays server-defaulted; long tables scroll horizontally instead of paginating client-side |
| T-14-41 | Information disclosure | `/api/v1/meta` | low | accept | The route serves only `name` and `version`; nothing else is rendered |
| T-14-42 | Elevation of privilege | edition selection | low | accept | Selecting an edition only changes a URL segment the server re-resolves; the client cannot activate, import or mutate any edition |
| T-14-SC | Tampering | web dependencies | low | accept | No package added; `layer_separation` also scans for remote URLs and HTML injection |
</threat_model>
