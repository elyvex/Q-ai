<objective>
Set and enforce the accessibility and responsive bar for every route: axe with zero serious/critical violations, Lighthouse accessibility ≥ 90, five keyboard-only core flows, and per-route verification at 390px and 1440px.

Purpose: R13 is the requirement that stops phase 14 from shipping a beautiful interface only a mouse user on a laptop can operate. Assert DOM and computed-style invariants, write the measured numbers into the evidence doc, and keep any rendered capture inside gitignored `web/.artifacts/`.
</objective>

<task type="auto">
  <name>Task 2: Keyboard-only completion of the five core flows</name>
  <files>web/e2e/keyboard.spec.ts</files>
  <precondition>14-15 Task 1's route list and 14-14's engine bootstrap are in place; `/ask` and `/catalog` are reachable on the seeded allow engine.</precondition>
  <action>
    Write `web/e2e/keyboard.spec.ts` with a local guard installed in `test.beforeEach`: replace the pointer entry points on the page object (`page.click`, `page.mouse.down`/`up`/`move`, `page.hover`) and on `Locator.prototype.click` with functions that throw `pointer use is forbidden in a keyboard-only walkthrough`. Restoring is unnecessary because each test gets a fresh page, but assert the guard is installed so a future refactor of the fixture cannot silently remove it.
    Implement the five flows with `page.keyboard.press` only (`Tab`, `Shift+Tab`, `Enter`, `Space`, `ArrowUp`/`ArrowDown`) plus `page.keyboard.type` for text entry, each with focus checkpoints (`expect(locator).toBeFocused()`) at every hop so a broken tab order fails at the hop, not at the end:
    read — from `/`, Tab to the reference navigation control, move with arrow keys to a surah, Enter, assert the ayah region changed and the URL deep link updated;
    search — Tab to the search field, type a fixture term, Tab to the submit control, Enter, assert hits render;
    copy citation — Tab to a citation's copy control, Enter, assert the clipboard content matches the displayed reference and checksum (grant clipboard permissions in the test's `context`); if the app reports a clipboard failure, assert the visible failure message instead — never a silent no-op;
    ask — Tab to the question field, type the fixture question, Enter (or Tab+Enter if Enter does not submit — record which), assert trace rows appear, then Tab to the cancel control and activate it, asserting the typed response;
    approve a source — on `/catalog`, Tab to a source card's action, Enter, confirm through the confirmation control with Enter, assert the audit row and new state appear.
    Add a focus-visibility assertion helper: for each checkpoint, assert the focused element's computed `outline-style` is not `none` or its `box-shadow` is not `none`, so keyboard focus is perceivable rather than merely programmatic. Apply it at least once per flow and at the first control of every route.
    If a flow cannot be completed without a pointer, do not weaken the test: record the blocking control and open failure in the SUMMARY and fail the spec — an unreachable control is the finding R13 exists to surface.
  </action>

  </verify>
