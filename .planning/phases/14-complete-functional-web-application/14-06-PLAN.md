<objective>
Add the RAG project lifecycle over HTTP and fix the two real gaps behind it: no resolver links a project name to a store, and the serve-time tool registry has no RAG backend at all (so `rag.query`/`rag.debug` answer `QAI-RAG-0310` today).

Purpose: R15 must honour the existing deny-by-default pattern while making the lifecycle usable. `SqliteRagReader` and `RagToolBackend` already implement create/import/query/tombstone semantics, including terminal tombstones and document deletion on deactivation — but they write through their own transactions with a per-project `audit_seq` counter and no chained audit event, and the CLI resolves a project by using its name as a path (unusable and unsafe over HTTP). This plan adds a name→store resolver rooted at `<data_dir>/rag/<uuid>`, refactors the three write paths so state and a chained audit event commit in one transaction, and exposes the lifecycle under `/api/v1/rag/*`.
Output: `/api/v1/rag/*` routes, `application::rag_projects`, audited RAG writes, and a served RAG tool backend.

**Route shape (locked by 14-CONTEXT.md):** mirrors the per-domain prefixes (`/api/v1/rag/*`, matching the existing `rag.*` tool names); durable writes deny-by-default with audit; no `/api/v1/admin/*`.
</objective>

**Code facts verified at HEAD (do not re-derive):**
- `SqliteRagReader` implements every needed operation but resolves a project by `name` **inside whatever database it was opened with**; the CLI creates `./{name}/index.db` and passes the *path* as the project argument. There is no name→store registry anywhere.
- `set_source_status` already: refuses invalid statuses, treats repeated status as idempotent, makes `tombstoned` terminal, computes a per-project `audit_seq` (`MAX(audit_seq)+1`) when none is supplied, and deletes `rag_embeddings`, `rag_documents`, and `rag_documents_fts` for `deactivated`/`tombstoned` sources. It uses `db.write_pool().begin()` directly, so it cannot share a `UnitOfWork`.
- `rag_sources.audit_seq` is a project-local counter, **not** a chained audit event. The project database still has the real `audit_events` table (all migrations are applied to it), and `audit::HashChainWriter::compute_chain_hash(prev_hash, event)` is a pure function usable inside a raw transaction.
- `rag_search` filters on `status == Active`, so deactivated/tombstoned sources are excluded from query results.
- `RagToolBackend::from_db(db)` wires reader + search over one database; `backend_query(project, query)` returns hits + `route_decision`; `backend_source_status` writes with `audit_seq: None`.
- `crates/cli/src/lib.rs` never calls `tools.set_rag_backend(...)`, so `POST /api/v1/quran/tool/rag.query|debug` currently returns `QAI-RAG-0310` "rag backend not configured". COVERAGE.md's L1 "✅ FULL" row is wrong about the HTTP leg; this plan fixes it.
- `rag::tombstone::{is_terminal, allows_reactivation}` exist but `set_source_status` implements the rule inline; do not add a third copy.
