<objective>
Surface the eight count instruments that have HTTP routes but no UI, through the instrument registry the Words view already uses — one descriptor each, one rules block, one checksum line, honest zero and honest typed failure.

Purpose: R6 is the cheapest honest coverage win in the phase — the server already answers `POST /api/v1/quran/count/{occurrences,hapax,collocation,numeric-report,missing-form,near-duplicates,interval,unusual-usage}`, `client.ts` simply never had methods for them and `WordsView` only knows five verbs. The work is a registry extension plus one shared invocation block, not eight screens. Two facts shape the design: the count routes send `meta.research_checksum = ""` and `reproducibility = {"tool": …}` only, so five of the eight payloads carry no server checksum at all; and `unusual-usage` is hard-wired to `CountingError::UnavailableDataset`, so its honest surface is a typed error.
Output: `web/src/api/instruments.ts`, `web/src/lib/count-instruments.ts`, `web/src/lib/invocation.ts`, `web/src/components/InvocationPanel.tsx`, and a registry-driven Counts section.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/quran/count/* | operator-typed target/profile/limit/threshold values cross here |
| server payload → rendered report | numeric and textual results become DOM text |
| browser → clipboard | an invocation string leaves the page as text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-34 | Tampering | client digest line | medium | mitigate | Digest is computed from the parsed payload and labelled `client`; it is never rendered as `research_checksum`, never compared against a server value, and never used as a verdict |
| T-14-35 | Spoofing | count provenance | high | mitigate | A count is printed only from the payload's `count`/rows; `zero under these rules` requires `count === 0` (or an explicit empty `hapax`/`hits` array), never an undefined field or a failed parse |
| T-14-36 | Information disclosure | typed errors | low | mitigate | `ErrorNote` receives only `code`, `summary`, `remedy`, `next_command` from the parsed `ApiError`; no response body or stack is rendered |
| T-14-37 | Denial of service | hapax / near-duplicates / collocation | medium | mitigate | `limit` and `threshold` are bounded in the descriptor (`1..=100`, `0..=1`) and the rendered row count is whatever the server capped it to — the UI adds no unbounded fetch loop |
| T-14-SC | Tampering | web dependencies | low | accept | No package is added; `npm run build` and `cargo test -p application --test layer_separation` gate the change |
</threat_model>
