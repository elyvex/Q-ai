<objective>
Ship the Ask workspace: submit a bounded research run, watch a cancellable trace, then read an evidence answer whose claims are individually re-verifiable and whose disagreements sit side by side.

Purpose: R1 and R2 are the phase's user-facing centre, and both depend on routes built in chunk 1 — `POST /api/v1/agents/runs` (+ SSE + cancel) from 14-01 and `GET …/answer` + `POST …/claims/{id}/verify` from 14-02. This plan consumes them and invents nothing: the trace renders the run's own events, the answer renders the server's document, and the only verdict the UI can show is the one the server returned. The `nav` work is the first of the two route-registration plans: `/ask` must land in `ROUTES`, `NAVIGATION`, `DIRECTORY` and the reachability matrix, and the new destinations join one secondary group rather than stretching the nine-link rail.
Output: `web/src/api/agents.ts`, `web/src/views/AskView.tsx`, the `/ask` route and secondary nav group, and the retargeted reachability row.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/agents/* | question text, run ids and claim ids cross here |
| agent run → rendered trace/answer | tool output, quotations and claims become DOM text |
| server verdict → UI badge | a citation verdict is the only source of "verified" |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-53 | Tampering | answer/trace text injection | high | mitigate | All fields render as React text children; `dangerouslySetInnerHTML` is rejected by `layer_separation`; the Markdown export is plain text built from the same fields |
| T-14-54 | Spoofing | `verified` badge | high | mitigate | The badge starts `unverified` and is set to `verified` only inside the resolved-200 branch of the server's verify call; a rejected call sets `mismatch`; no client-side text comparison exists |
| T-14-55 | Information disclosure | run snapshot / errors | medium | mitigate | The snapshot is already redacted server-side (14-01); the UI prints only the contract fields and shows `code`/`summary`/`remedy` from the error envelope, never a raw body |
| T-14-56 | Denial of service | SSE / polling | medium | mitigate | One `EventSource` per run, closed on `done` and on unmount; polling stops at a terminal state and is capped at 120 ticks with a visible reason; the server caps the stream at 60 s |
| T-14-57 | Repudiation | cancel action | low | accept | Cancel is a cooperative request the server audits; the UI shows `cancel requested` until the server reports a terminal disposition and never claims the stop itself |
| T-14-SC | Tampering | web dependencies | low | accept | No package added (native `EventSource`); build + `layer_separation` gate the change |
</threat_model>
