<objective>
Add the answer contract surface: a deterministic projection from a completed run's stored evidence into sectioned claims with claim-level citations, plus a server-side re-verify endpoint that fails closed through the shared citation verdict mapping.

Purpose: R2 cannot be satisfied by rendering raw tool payloads (today's RAG Debug surface). The answer must be a first-class typed document whose claims are individually re-verifiable, so the UI can render green/red inline and never present an unverified quotation as an answer. Assembly is deliberately pure (no I/O) so determinism and claim-id stability are testable; verification is the only I/O step and it reuses the existing `citations` crate plus the reader path.
Output: `GET /api/v1/agents/runs/{id}/answer` and `POST /api/v1/agents/runs/{id}/claims/{claim_id}/verify`, an `application::answer` module, and a production `citations::CitationSource` implementation (none exists today — only a test fake in `crates/citations`).

**Independence note:** this plan does not link against `application::agent_run` (14-01). It reads the run through the existing `application::db::get_job` and the documented `agent.evidence` checkpoint schema, which 14-01 writes and this plan consumes. That keeps both plans compilable and testable in the same wave; the integration test at the end of Task 3 is the cross-plan proof.
</objective>

**Code facts verified at HEAD (do not re-derive):**
- `citations::CitationSource` (edition_exists + fetch_ayah_text) has **no production implementation** — only `FakeSource` inside the citations crate's test module. This plan adds the first one, in `server` (allowed deps: `citations`, `quran-core`, `tool-registry`).
- `citations::require_exact` is the single shared verdict→error mapping (`QAI-QUR-0323/0324/0325`); `citation_handler` in `api.rs` already uses it to refuse a 200 on a hard failure. Reuse it, do not write a second mapping.
- `citations::Citation` requires `surah: SurahNumber` and `ayah: AyahNumber` typed values — parse with `quran_core::parse(&canonical_reference)` and reject non-ayah references as `QAI-QUR-0321`.
- `ToolRegistry::get_ayah` returns `(ToolResult<Vec<AyahView>>, BackendMeta)`; the first `AyahView`'s `canonical.arabic_text()` is the canonical text and `meta.edition_slug`/`edition_version` identify it.
- `application::db::get_job` redacts `payload_json`/`checkpoint_json`/`error_json` before returning. Evidence fields are Arabic text and reference strings; do not name any evidence key `token`, `secret`, `password`, or `key` or redaction will alter it.
- Malformed JSON inside a checkpoint column is scrubbed as free text by `redact_json_text_column` and comes back as a string — treat a non-object checkpoint as `QAI-AGENT-0306`, not as empty evidence.

  <action>
    Create `crates/application/src/answer.rs` (register `pub mod answer;` in `crates/application/src/lib.rs` alphabetically).

    Types (all `serde::Serialize/Deserialize`, fully doc-commented, no `unwrap`):
    `AnswerDoc { schema: u8, question: String, edition: Option<String>, sections: Vec<Section>, disagreements: Vec<DisagreementGroup>, usage: serde_json::Value, checksum: String }`;
    `Section { id: String, title: String, claims: Vec<Claim> }`;
    `Claim { claim_id: String, text: String, citations: Vec<ClaimCitation>, disagreement_group: Option<String> }`;
    `ClaimCitation { citation_id: String, canonical_reference: String, edition_slug: String, edition_version: String, quotation: String, deep_link: String, urn: String, text_hash: String }`;
    `DisagreementGroup { group_id: String, reference: String, positions: Vec<DisagreementPosition> }`, `DisagreementPosition { edition_slug, edition_version, quotation, claim_id }`.

    `pub fn assemble(evidence: &serde_json::Value) -> Result<AnswerDoc, AnswerError>`:
    - Validate `evidence.schema == 1`, `evidence.evidence` is an array, `evidence.question` is a non-empty string; anything else → `AnswerError::MalformedEvidence(detail)`.
    - One claim per evidence row, ordered by the row's position in the array (no sorting, no dedup — order is part of the contract). `claim_id = format!("claim-{:03}", index + 1)`; `text` = `"Ayah {reference} was returned by the run's search and read from edition {slug}@{version}."` — a factual statement about the run, never an interpretation of the verse.
    - Citation per claim: `citation_id = format!("cit-{run_claim}-{citation_index}")`, `canonical_reference`/`edition_slug`/`edition_version`/`quotation`/`text_hash` copied verbatim from the evidence row, `deep_link` and `urn` built with the frozen `citations::deep_link` / `citations::citation_urn` helpers (never reconstructed by hand, ADR-0111).
    - Group by `(surah, ayah)` parsed from `canonical_reference`; when a group has ≥ 2 distinct `(edition_slug, edition_version)` pairs, emit a `DisagreementGroup` and set `disagreement_group` on each participating claim. One-edition evidence yields `disagreements: []`.
    - One section `{id: "matches", title: "Evidence returned by the run"}` holding all claims; `usage` copied from `evidence.usage`; `checksum` = `sha256:` over the canonical JSON of `{question, sections, disagreements}` using `domain::hashing::canonical_json_bytes` (reuse the frozen helper; do not write a new hasher).
    Determinism: the function must be a pure function of its input — no `SystemTime`, no `HashMap` iteration order (use `BTreeMap`), no UUID generation.

    `AnswerError` variants `MalformedEvidence(String)` and `UnsupportedSchema(u8)`, implementing `storage::error::Diagnostic` with namespace `QAI-AGENT`, codes 0306 and 0307, remedy pointing at `qai agents runs show --help`.

    Tests in `crates/application/tests/answer.rs` (no database needed): (i) a two-ayah single-edition fixture yields 2 claims, each with exactly one citation, `disagreements` empty; (ii) calling `assemble` twice yields byte-identical serialized output and identical claim ids; (iii) a two-edition fixture for the same reference yields one group with two positions and `disagreement_group` set on both claims; (iv) `evidence` missing/`schema:2`/`evidence: {}` each return the typed error; (v) the doc never contains a claim with an empty `citations` array (assert across a fixture with 50 rows).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/agents/runs/{id}/answer | a run id selects durable evidence |
| answer document → reader | claim citations must resolve to the same text the reader shows |
| stored evidence → verification | a stale quotation must fail, not be repaired |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-06 | Spoofing | claim citations | high | mitigate | Deep link and URN come only from `citations::deep_link`/`citation_urn`; quotation text is copied verbatim from the tool result, so a claim cannot point at text it did not receive |
| T-14-07 | Tampering | stored evidence | high | mitigate | Verification always re-reads live canonical text; a mutated stored quotation produces `QAI-QUR-0323` with the first-difference index, never a repaired match |
| T-14-08 | Information disclosure | answer payload | low | mitigate | Answer contains only public canonical text, edition identity, and run metadata; job reads go through the redacting `get_job` |
| T-14-09 | Denial of service | claim verify fan-out | medium | mitigate | One citation per claim in v1 and a bounded claim count (evidence rows ≤ `max_steps` ≤ 16), so a verify call is at most 16 `get_ayah` reads |
| T-14-10 | Elevation of privilege | answer route | low | mitigate | Routes are read-only (GET/POST-verify with no durable write); no approval gate needed, and none is added |
| T-14-SC | Tampering | dependency edges | low | mitigate | No new dependency in this plan; `arch-check` gates the existing edges |
</threat_model>
