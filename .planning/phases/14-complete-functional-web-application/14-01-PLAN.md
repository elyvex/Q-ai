<objective>
Add the missing agentic-research HTTP surface: a durable, cancellable agent run that executes real read-only tools, persists a per-step trace, and streams progress over SSE while keeping snapshot polling as the fallback.

Purpose: R1 is the phase's largest backend gap — `crates/agent-runtime`, `crates/agency`, `crates/llm`, and `crates/model-router` are all four-line placeholders, so "run a controlled agent" has to be built on the machinery that actually exists: the durable job queue (cooperative cancellation, checkpoints, `job_events`), the shared tool dispatcher, and the chained audit trail. This plan deliberately does not invent a model call: the run is a deterministic research loop over registered tools, which is honest, testable, and produces exactly the evidence the answer contract (14-02) needs.
Output: `POST/GET /api/v1/agents/runs`, `…/runs/{id}/events` (SSE), `…/runs/{id}/cancel`, `GET /api/v1/agents/runs`, plus the `RouteServices` seam every later chunk-1 plan extends.

**Route shape (locked by 14-CONTEXT.md):** `/api/v1/agents/*`, mirroring the per-domain prefixes; no `/api/v1/admin/*`; existing `Envelope` + `QAI-*` error envelope only; no per-area token.

**Evidence checkpoint schema (consumed verbatim by 14-02 — do not change without updating 14-02):**
`{"schema":1,"question":str,"edition":str|null,"steps":[{"seq":u64,"tool":str,"params":object,"status":"ok"|"error","canonical_references":[str],"checksum":str}],"evidence":[{"reference":str,"edition_slug":str,"edition_version":str,"quotation":str,"text_hash":str,"checksum":str}],"usage":{"steps":u64,"tool_calls":u64,"elapsed_ms":u64,"max_steps":u64}}`, stored as the named checkpoint `agent.evidence` via `JobContext::checkpoint_named`.

## Trust Boundaries

| server → tool registry | user text becomes tool parameters |
| server → SQLite job store | run state, trace, and evidence become durable rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-01 | Tampering | POST /agents/runs payload | high | mitigate | Question is trimmed, length-capped (2000), and passed only as a typed `SearchToolParams`; no string concatenation into SQL or shell; unknown fields ignored by serde |
| T-14-02 | Information disclosure | GET /agents/runs/{id} | medium | mitigate | Snapshot reads through `application::db::get_job`, which redacts payload/checkpoint/error columns; run ids are UUIDs; no cross-run listing beyond the filtered kind |
| T-14-03 | Denial of service | SSE /agents/runs/{id}/events | medium | mitigate | Stream hard-capped at 60 s; 250 ms poll interval; run step count clamped to 16; existing 30 s request timeout layer is bypassed by streaming, so the cap is the bound |
| T-14-04 | Elevation of privilege | run execution | high | mitigate | Handler can only call `ToolRegistry` read methods (`search`, `get_ayah`) — no mutating tool name reaches it; `dispatch_registered_tool` mutating gates are untouched |
| T-14-05 | Repudiation | run lifecycle | high | mitigate | Enqueue and cancellation each stage one chained audit event in the same UnitOfWork as the state change (existing `stage_job_audit` / `stage_operator_audit` paths) |
| T-14-SC | Tampering | dependency edges | high | mitigate | `futures-core` is already locked; allowlist entry added in the same commit; `cargo xtask arch-check` gates the edge |
