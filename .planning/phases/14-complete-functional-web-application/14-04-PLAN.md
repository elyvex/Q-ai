<objective>
Add the source-catalog curation surface: discover/quarantine/license-review/stage/diff/approve/activate/deprecate/rollback routes over the existing `sources`/`source_versions`/`source_files`/`source_state_transitions`/`approvals` tables, with trust profiles and same-UnitOfWork audit.

Purpose: R4 is the only backend area whose storage layer is already complete — `crates/storage-sqlite` implements every `SourceRepository` method (insert, transition, record_transition, insert_approval, upsert_principal) and `crates/sources` owns the legality + precondition rules. What is missing is the application service and the HTTP surface. This plan therefore adds no table and no repository method: it composes the existing pieces so the CLI's read-only `source list/show` gains a full curation path without a second state machine.
Output: `/api/v1/catalog/*` routes, `application::catalog`, two audit actions, and one justified domain transition edge.

**Route shape (locked by 14-CONTEXT.md):** `/api/v1/catalog/*`; durable writes deny-by-default with audit.
</objective>

**Code facts verified at HEAD (do not re-derive):**
- `0002_sources.up.sql` already models the whole pipeline: `state` CHECK includes `Discovered/PendingReview/Downloading/Downloaded/Validating/ValidationFailed/Staged/Approved/Indexing/Active/Deprecated/Quarantined/Removed`; `trust_level` has 8 values; `license_status` has 7; the table CHECK refuses `Approved/Indexing/Active` unless `content_hash`, non-`Unknown` license, `approved_by`, and `validation_report` are all present — so a precondition bug also fails at the DB, but the API must still return a *named* remedy rather than a constraint error.
- `sources::StateMachine::is_legal_transition` / `transition` / `check_approved_preconditions` are the single legality + precondition source. `transition` calls `check_approved_preconditions` when the target is `Approved`.
- `sources::StateMachine` has **no `(Deprecated, Active)` edge**, so byte-identical rollback is impossible today. `AuditAction::SourceRolledBack` already exists, i.e. rollback was always intended.
- `application::audit_bridge::audited_source_activation` / `audited_source_deactivation` already write the generation/tombstone workflow rows plus the chained audit event in the caller's UnitOfWork.
- `application::db::get_source/list_sources` read with sqlx directly and redact; new service reads use the same direct-sqlx precedent, so no `storage` trait file changes are needed in this plan.
- `sources::SourceState` is `#[serde(rename_all = "snake_case")]` while the DB stores PascalCase — parse it with a local `match`, not serde. `TrustLevel` and `LicenseStatus` variant names equal their DB CHECK values, so `serde_json::from_value(serde_json::Value::String(s))` parses them.
- `SourceVersion` (the `sources` domain struct) has 21 fields; mapping the DB row to it is the price of reusing `StateMachine::transition` instead of duplicating its rules.

    `pub enum CatalogError` → `Diagnostic` namespace `QAI-SRC`: 0300 invalid input, 0303 illegal transition (message names `from → to`), 0304 unknown source/version, 0306 precondition unmet (carry the specific unmet item and the remedy `qai source show <id>`), 0309 license gate, 0326 policy denial.

    Row mapping: `fn version_from_row(row) -> Result<sources::SourceVersion, CatalogError>` built from a full-column SELECT (`id, source_id, version, schema_version, state, trust_level, license_status, license_json, manifest_blob_id, manifest_hash, content_hash, source_urls, publication_date, imported_at, validated_at, approved_at, approved_by, activated_at, deprecated_at, quarantine_reason, validation_report, notes, created_at`) — map `state` with a local PascalCase `match` into `SourceState`, parse `trust_level`/`license_status` through serde on a JSON string, and parse ids/timestamps via the `domain` types' existing `FromStr`/`TryFrom`. This mapping is the only place the DB shape meets the domain shape; document that.

    Mutations (each in one `write()` UnitOfWork):
    - `quarantine(id, vid, reason, operator)`: legal from any state (the state machine already has `(_, Quarantined)`); set `quarantine_reason`, transition, record transition, audit `SourceQuarantined` with `before`/`after` state and the reason.
    - `license_review(id, vid, license_status, note, operator)`: parse the license value (reject `Unknown` when the version would otherwise be approvable — i.e. when `state` is `Staged` or later, return 0309 with remedy "record a concrete license before approval"); UPDATE `license_status` and `notes`; audit `SourceLicenseReviewed`.
    - `set_trust(id, vid, trust_level, operator)`: parse and UPDATE `trust_level`; audit `PrincipalChanged`-independent — use `SourceValidated` with `after: {"trust_level": …}` and a reason naming the trust change (do not invent a new action for this one; the trust profile is review metadata).
    - `stage(id, vid, operator)`: `StateMachine::transition` to `Staged`, record transition, audit `SourceStaged`.
    - `approve(id, vid, approver_principal, note)`: `ensure_principal` the approver, set `approved_by`/`approved_at` on the row first, then `StateMachine::transition(&mut version, Approved, …)`; on `ApprovalPreconditionNotMet` return `0306` naming the missing item; insert the `approvals` row (`kind: "source.approve"`, `subject_urn: "source_version:<vid>"`, decision `approved`) in the same UnitOfWork; audit `SourceApproved` + `ApprovalGranted`.
    - `activate(id, vid, operator)`: require `state == Approved`; call `audited_source_activation(&mut *uow, vid, "catalog", &format!("source_version:{vid}"), &mutation)` then transition to `Active` and record it — all in the same UnitOfWork so the generation row, activation audit, and state change cannot split.
    - `deprecate(id, vid, reason, operator)`: `audited_source_deactivation` when the version is the Active one, plus transition to `Deprecated`, audit `SourceDeactivated`-equivalent (`SourceRolledBack` is reserved for rollback; use `SourceValidated` with a deprecation reason if no dedicated action exists — prefer adding nothing further).
    - `rollback(id, target_vid, operator)`: within one UnitOfWork, deactivate whichever version is currently `Active` for the source (tombstone + audit), then activate `target_vid` (must be `Deprecated`) using the new edge, and audit `SourceRolledBack` with `before {"active": <old>}` / `after {"active": <target>}`. Return both version rows plus `content_hash` values so the caller can assert identity.
    - `diff(id, from_vid, to_vid)`: SELECT `relative_path, declared_hash, observed_hash` for both versions, compute added/removed/changed/unchanged (changed = same path, different `observed_hash` falling back to `declared_hash`), persist one `difference_reports` row (`subject_urn: "source:<id>"`, `from_version`, `to_version`, `differ: "source_files"`, `differ_version: "1"`, `summary_json` with the four counts, `details_json` with the path lists), and return the report.

    No network access, no file reads: every operation works on rows already present.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/catalog | source/version ids, license and trust values, approver identity |
| catalog → audit/approvals | activation and rollback are durable, attributable writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-17 | Elevation of privilege | approve/activate/rollback | critical | mitigate | `StateMachine` legality + preconditions are the only path; DB CHECK is the backstop; routes deny by default and require a named approver principal |
| T-14-18 | Tampering | rollback | high | mitigate | Rollback reactivates an unchanged row (content_hash preserved) rather than copying content; test asserts byte-identical hashes before/after |
| T-14-19 | Repudiation | transitions | high | mitigate | `source_state_transitions` row + chained audit event written in the same UnitOfWork as the state update; count asserted per mutation |
| T-14-20 | Spoofing | approver identity | high | mitigate | Approver is upserted through `ensure_principal` and written to `approved_by` + the `approvals` row in that UnitOfWork; an empty approver is refused |
| T-14-21 | Information disclosure | version detail | low | mitigate | Only catalog metadata is exposed; license_json/notes are author-controlled; no blob bodies are read |
| T-14-22 | Denial of service | diff | low | mitigate | File lists are bounded by existing catalog page limits (1000 rows); diff is a single pass over two path sets |
| T-14-SC | Tampering | state machine change | high | mitigate | Exactly one new edge, unit-tested both ways, audited via the pre-existing `SourceRolledBack` action |
</threat_model>
