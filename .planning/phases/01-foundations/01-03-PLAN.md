<objective>
Close FND-05 by extending the existing leased SQLite queue and backend-neutral worker contracts with named durable checkpoints, per-kind retry policy, explicit retry/cancel controls, and auditable lifecycle transitions. This plan implements D-01, D-02, D-03, D-11, D-14, D-15, and D-16. It reuses the current `jobs` table, `JobQueue`, `HandlerRegistry`, `Worker`, `SqliteJobQueue`, lease recovery, deterministic backoff, and the audited `UnitOfWork`; it does not add a broker, a second queue, or a new package.

Purpose: Make long-running foundation work resumable and operationally inspectable without allowing retries, cancellation, or audit claims to outrun lease ownership and durable state.

Output: Named checkpoint and cancellation-disposition contracts, owner-safe SQLite transitions, lifecycle audit actions, explicit `qai job retry`/`qai job cancel`, and real-SQLite recovery/cancellation/audit tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Operator CLI → job request | Job ids, retry intent, and cancellation intent enter the application boundary. |
| Worker → leased SQLite row | Handler callbacks, lease ownership, and checkpoint/cancellation state cross concurrent workers. |
| Queue transition → audit chain | Job state and trust evidence are persisted in one transaction. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-LEASE | Elevation of privilege / denial of service | SQLite job transitions | high | mitigate | Require lease owner for heartbeat/checkpoint/terminal writes; cancellation only sets a durable request and never clears ownership. |
| T-03-RETRY | Denial of service | Worker retry policy | high | mitigate | Resolve bounded per-kind policy, retain deterministic jitter, dead-letter exhaustion, and require explicit retry. |
| T-03-CHECKPOINT | Tampering / repudiation | `JobContext` and checkpoint column | high | mitigate | Persist versioned named checkpoints at handler boundaries, recover the last committed value, and test lease-expiry resume. |
| T-03-SECRET | Information disclosure | job CLI/JSON/audit payloads | high | mitigate | Allowlist lifecycle metadata and apply existing redaction to payload/checkpoint/error JSON before emission. |
| T-03-CONCURRENCY | Tampering | `claim_next`/lease recovery | medium | mitigate | Keep atomic SQL predicates, parsed timestamp ordering, and real-SQLite double-claim/expired-lease tests. |
</threat_model>
