<objective>
Close FND-04 by composing every authoritative durable change with its required provenance, audit, and outbox records in the existing shared transaction. This plan implements D-01, D-02, D-03, D-09, D-10, and D-12 while preserving the existing approval-gated Quran, source, outbox, and hash-chain primitives. It is a brownfield seam repair: do not introduce a second transaction manager, a new event hash format, or a parallel audit writer.

Purpose: Make the durable trust record impossible to split from the state it describes, and prove the result with real SQLite fault injection rather than a compile-only or mock-only assertion.

Output: A reusable application-level audited mutation composition, all relevant source/import/approval/activation/rollback paths routed through it, and rollback/tamper acceptance tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Application service → `UnitOfWork` | A domain operation and its trust records cross the transaction boundary. |
| Audit/outbox/provenance repositories → SQLite | Hash-chain, source, and projection state are persisted together. |
| Human approval → canonical writer | Approval identity and subject binding cross from operator input to a canonical mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-ATOMICITY | Tampering / repudiation | `AuditedMutation`, `SqliteUnitOfWork` | critical | mitigate | Enforce one shared transaction and fault-inject domain, provenance, outbox, audit, and commit boundaries; assert no partial row remains. |
| T-02-PROVENANCE | Tampering / information disclosure | provenance and outbox writes | high | mitigate | Require the universal provenance record and required outbox event before the audited commit; use the existing layer/attribution invariants. |
| T-02-CANONICAL | Elevation of privilege | Quran activation/approval path | high | mitigate | Keep `CanonicalWriter`/`ApprovalToken` checks, exact subject binding, and importer staging-only behavior; add negative tests. |
| T-02-RECOVERY | Repudiation | audit verifier and CLI | high | mitigate | Recompute sequence, predecessor links, and row hashes; expose `qai audit verify` and recovery guidance for gaps/tampering. |
| T-02-SQL | Tampering | real-SQLite test/finalization queries | medium | mitigate | Use SQLx bound parameters and existing repository methods; do not interpolate user identifiers into new SQL. |
</threat_model>
