Close FND-06 by making the existing durable worker lifecycle visibly owned by `qai serve` and changing the one-shot Quran import path to enqueue/report work only. ## Reuse ledger

| Current seam | Demonstrated gap | Smallest closing change |
|---|---|---|
| `Worker::run_once` and lease watchdog | No host-facing stop signal; no safe in-flight shutdown contract | Add a Tokio watch-based shutdown path that requests cancellation and joins the active handler |
| `build_worker` / `HandlerRegistry` | `qai serve` has no production registry and one-shot import constructs a private worker | Add a default registry/host in application and pass the host to the serve composition |
| `run_import_job` | Enqueues and immediately drains in the CLI process | Rename/split into an enqueue-only result consumed by `cmd_import` |
| `qai quran import` trycmd flows | Assume the import command is synchronous | Run the real host in the existing test harness and synchronize on persisted job state |
| `qai serve` | Starts the HTTP future without a joined worker or signal lifecycle | Select the server and worker futures, notify on termination, await cleanup, and preserve the migration remedy |

## Context-budget rationale

This plan retains fourteen files because they form one serial host-boundary slice: the leading tracer wires the worker host to the real `qai serve` binary, the second task converts the existing import path to enqueue/report semantics, and the third task updates the already-existing CLI harness plus four existing snapshots that cannot be truthfully updated before the host/import contracts exist. Seven files are production seams on the same path, two are test harnesses, four are existing snapshots, and one is the repository evidence record. Splitting the snapshots into a later plan would leave the current test target knowingly red after this plan; moving the host composition away from its real binary proof would break the tracer-first slice. The calibrated projection is 42,000 tokens for three bounded tasks, below the smart-zone threshold, and no new package, migration, or corpus behavior is introduced.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Signal/server lifecycle → worker host | Process termination and server completion cross into durable job execution. |
| One-shot CLI → SQLite job row | Operator input and manifest metadata become a queued job that a separate process will execute. |
| Worker handler → audited domain transaction | Existing handler work changes authoritative state while the host owns lease/cancellation state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-HOST | Denial of service / elevation of privilege | `qai serve` worker lifetime | high | mitigate | Use one readiness-gated host, bounded polling, explicit error propagation, and a joined shutdown; reject detached task ownership. |
| T-04-SHUTDOWN | Tampering / repudiation | shutdown-aware `Worker` | high | mitigate | Persist a cooperative cancellation request, await the active handler’s terminal/checkpoint transition, and test signal-driven completion before process return. |
| T-04-ENQUEUE | Tampering | import enqueue and catalog setup | high | mitigate | Validate before enqueue, bind job parameters, use the 01-02/01-03 audited transaction seams, and return only an inspectable queued id. |
| T-04-LEASE | Elevation of privilege / denial of service | host-owned lease transitions | high | mitigate | Reuse 01-03 owner checks; never clear a lease from the serve shutdown path or a one-shot command. |
| T-04-SECRET | Information disclosure | host logs and CLI queued result | high | mitigate | Allowlist job metadata, apply the existing redaction layer to errors/JSON, and keep raw payloads/checkpoints out of host diagnostics. |
| T-04-SCOPE | Elevation of privilege | handler registry | medium | mitigate | Register only existing handlers and preserve approval/canonical boundaries; unknown kinds follow the established dead-letter policy. |
