# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend surfaces (Web GUI, TUI, CLI). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: narrator record view, chain path traversal view, identity review workflow (approve/reject/dispute/supersede). Cross-surface parity: CLI (`CommandOutput { human, json }`), TUI (ratatui screens), Web (React + CSS tokens). Typed tool results (`ToolResult`) and `research_checksum` on every envelope. No shadcn — plain React + CSS tokens (web), ratatui (TUI), plain-text (CLI).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Rust CLI + ratatui TUI + React/Vite Web; shadcn gate not applicable) |
| Preset | not applicable |
| Component library | none — CLI plain-text renderer (`CommandOutput { human, json }`); TUI ratatui widgets (Block, Table, List, Paragraph); Web plain React components + CSS tokens (no component library) |
| Icon library | none (text-only CLI/TUI; Web uses text labels only, no icon-only actions) |
| Font | CLI/TUI: terminal monospace (inherited); Web: `system-ui, 'Segoe UI', Roboto, sans-serif` (from `web/src/index.css`); Arabic names rendered with `--layer-font-arabic` (`'Amiri', 'Scheherazade New', 'Noto Naskh Arabic'`) — narrator names are data, never typeset by the tool chrome |

Focal point per surface (visual hierarchy — summary first, detail below, truncation always inline on the summary line, never hidden): narrator record → stable-id header line + primary name; chain path → the count/paths summary line; identity review → the `<verb> <id> (<decision>)` line; TUI → the table header row then rows; Web → the section heading then the list. No icon-only actions exist; every status is a word (`pending`, `accepted`, `rejected`, `superseded`, `disputed`, `uncertain`, `confirmed`), never color or glyph alone.

## Spacing Scale

Declared values (must be multiples of 4). Web uses the px scale; CLI/TUI use character/cell grids.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps between id and name (Web) |
| sm | 8px | Compact row spacing, badge padding (Web) |
| md | 16px | Default element spacing, section padding (Web) |
| lg | 24px | Card/panel padding, section breaks (Web) |
| xl | 32px | Layout gaps between narrator card and rijal list (Web) |
| 2xl | 48px | Major section breaks (Web) |
| 3xl | 64px | Page-level spacing (Web) |

Exceptions: none (Web). CLI/TUI spacing is cell-based (see terminal grid below).

Normative terminal grid (character columns/cells, not px — literal output bytes pinned by trycmd snapshots and ratatui constraints):

| Rule | Value | Where |
|------|-------|-------|
| Summary line | column 0, single line | every read verb (`narrator …`, `rijal …`, `trace …`) |
| List indent | 2 spaces | quotation/edge rows (`  narrator:a -TRANSMITS-> narrator:b`) |
| Remedy indent | 6 spaces | error `      remedy: …` / `      next: …` lines (CLI) |
| Truncation marker | inline ` (truncated)` + `\nincomplete: <reason>` verbatim | every partial result, human + JSON output |
| Row rhythm | single-spaced, one finding per line | all CLI human output |
| TUI table | Block borders, columns: id 16, kind 10, decision 10, summary Min(10) (mirrors `render_annotation_review`) | narrator/identity review screens |
| Web grid | CSS: `gap: var(--space-md)` (16px) between cards; rijal sources stacked with 8px gap | narrator record view |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Web: `#ffffff` (light) / `#16171d` (dark) bg; CLI/TUI: terminal default (zero color codes) | Background, surfaces, all CLI output inherits operator theme |
| Secondary (30%) | Web: `#f1f5f9` (`--layer-translation-bg`) cards/sidebar/nav; TUI: ratatui default block borders | Cards, sidebar, nav, narrator record card, rijal source rows |
| Accent (10%) | Web: `#aa3bff` (light) / `#c084fc` (dark); CLI: `#a00` truncation only | Specific enumerable set only (see below) |
| Destructive | Web: `#dc2626`; CLI/TUI: red (ratatui `Color::Red`) | Destructive actions only (reject confirmation) |

Accent reserved for: (1) truncation banners — `truncated: <reason>` (Web `<p className="graph-truncated">`, TUI yellow Paragraph, CLI inline ` (truncated)` + DOT/SVG banners); (2) pending-review status chips (`pending`); (3) `uncertain` confidence badges on computational links; (4) the primary CTA button. Accent is never applied to headings, node/edge ink, or canonical text. Provenance layers B/C/D display via the existing layer tokens: B → `--layer-canonical-*` (canonical text), C → `--layer-translation-*`, D → `--layer-annotation-*` (uncertain/computational). Rijal sources (per-scholar) each render their own scholar badge using the secondary token — never merged into a single consensus color.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `qai isnad narrator --id narrator:{slug}` — open a narrator record (e.g. `qai isnad narrator --id narrator:abu-hurayra` → `narrator:abu-hurayra — Abu Hurayra (… variants)` + rijal source rows). Web button label: `Open narrator`. TUI key: `n`. |
| Narrator record heading | `{stable-id} — {primary_name}` (e.g. `narrator:abu-hurayra — Abu Hurayra`). Empty variants render `variants: (none)`. |
| Rijal source row | `{scholar_name} — {source_citation} — {grading_value or "no grade"} ({decision})` per scholar, one row per scholar; header `rijal sources ({N} scholar(s)):`. Never a single consensus grade. |
| Name variants line | `variants: {v1}, {v2}, …` (Arabic script variants, kunya, laqab, nisba) |
| Empty state (narrator) | `narrator {id}: not found` (typed, exit 0 Web shows `No narrator found for {id}.` + retry input). |
| Empty state (rijal) | `rijal sources for {id}: 0 scholar(s)` — zero-count line, never generic "No data". |
| Empty state (trace) | `no path (complete search)` only when `truncated == false`; `unknown (truncated)` when truncated. |
| Empty state (identity queue) | `identity review: 0 pending` (zero-count line). |
| Error state | `[QAI-ISNAD-NNNN] <detail>` + `Remedy: <fix>` + `Next: qai isnad … --help` (code + remedy + next command always together, never a bare message). Web: `<p role="alert">{summary}</p>` with remedy text. TUI: red Paragraph. Examples: unknown narrator → `NOT_FOUND`; CHECK violation → `VALIDATION`; malformed input → usage error. |
| Truncation rendering | `… (truncated)` + `incomplete: <reason>` verbatim on the summary line (CLI); `truncated: {reason}` banner (Web `<p className="graph-truncated">`); yellow `truncated: {reason}` (TUI). Partial results never rendered as absence or negative claims. |
| Identity review report line | `<verb> <assertion-id> (<pending \| accepted \| rejected \| superseded \| disputed>) by <reviewer> at <decided-at>[ (supersedes <old-id>)]` (e.g. `accepted nia-001 (accepted) by owner at 2026-10-17T…`). Suggestions stay labeled `pending` with algorithm attribution until a recorded human decision. |
| Destructive confirmation | `identity reject <id>` requires explicit `--yes` or terminal `Type APPROVE to reject \`<id>\``; refusal renders `refusing to reject without --yes` (non-terminal) or `not approved`. Success renders `<summary> (audit #<seq>)`. Web: modal dialog with `Reject {id}?` heading + `Confirm reject` button + `Cancel`; TUI: confirmation Paragraph with `APPROVE` prompt. |
| Confidence band labels | `high (>0.9)`, `medium (0.7-0.9)`, `low (<0.7)` — all suffixed ` (uncertain)` until owner confirmation (e.g. `0.85 (uncertain)`). Never rendered as a percentage alone. |
| Uncertainty marker | Every computational link/identity match carries the literal `uncertain` label until confirmed; confirmed links render `confirmed` with reviewer + decided_at. |

## Cross-Surface Parity

| Surface | Narrator record | Chain trace | Identity review |
