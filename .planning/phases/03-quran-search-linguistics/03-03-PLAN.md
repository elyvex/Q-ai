## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arg → counting service | untrusted root/lemma/profile/mode text crosses into SQL aggregation |
| lexicon derived tables → count report | counts must be exact SQL over derived rows, never FTS frequency guesses |
| result contract → consumer | a numeric report without CountingRules is an invalid result |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10 | Tampering | new lexicon count SQL | high | mitigate | Typed `.bind(...)` parameters only; no string-concatenated SQL; tests exercise root/lemma values. |
| T-03-11 | Repudiation | numeric output without stated rules | high | mitigate | Every report embeds `CountingRules`; tests assert `rules.datasets` and `rules.multi_analysis_handling`. |
| T-03-12 | Information disclosure | dataset attribution missing | medium | mitigate | Root/lemma reports name the active `<slug>@<version>` from the dataset row; no guessed dataset name. |
| T-03-13 | Denial of Service | unbounded aggregation | low | accept | Counts are aggregate SQL over indexed dataset_id joins; result sets are scalars, not row dumps. |
| T-03-SC | Tampering | cargo/npm installs | high | accept | No new packages proposed; changes stay inside existing crates. |
</threat_model>
