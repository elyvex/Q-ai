## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent/tool caller → registry | untrusted tool input crosses into search/lexicon backends |
| derived artifacts → doctor | diagnostics must be read-only and truthful |
| registry result → consumer | results must carry attribution and normalization rules |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-26 | Tampering | registry poisoning | high | mitigate | New tools return `ToolResult` envelopes built from verified hits/attributed analyses; no result bypasses canonical quotation or attribution. |
| T-03-27 | Repudiation | doctor auto-repair | high | mitigate | The soak asserts doctor is read-only and only reports drift (`QAI-IDX-0101`); no repair path is added. |
| T-03-28 | Denial of Service | unbounded tool latency | medium | mitigate | Budget artifact gates fixture runs; regex/limit caps unchanged; the tool surface reuses the clamped search paths. |
| T-03-29 | Information disclosure | tool result without attribution | medium | mitigate | `analysis_sources`/`normalization_rules` are required by tests on every new tool. |
| T-03-SC | Tampering | cargo/npm installs | high | accept | No new packages; tools use existing crates and dev-deps. |
</threat_model>
