<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted spaceless query text → skeleton/trigram recall | CLI arg / fixture input crosses into normalization + skeleton stores |
| derived skeleton/trigram store → verified hit | recall candidates must be re-verified against canonical |
| cross-ayah window → ayah-level result | a window match must not be presented as one verse |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-06 | Tampering | concatenated query binding | high | mitigate | Query normalized through L6.skeleton then bound; `must_not_contain` precision anchors in every golden row; no SQL concatenation. |
| T-03-07 | Spoofing | cross-verse fragment presented as one verse | high | mitigate | Golden rows assert `spans_ayah_boundary = true` for window hits and ayah-level-win dedup. |
| T-03-08 | Denial of Service | unbounded trigram recall / scan fallback | medium | mitigate | Recall bounded by trigram postings with a scan fallback; `limit` stays clamped `1..=1000`; `max_ayah_span` defaults to 3. |
| T-03-09 | Repudiation | heuristic concatenated match without explanation | medium | mitigate | Every returned hit carries a non-empty `segmentation`; golden rows assert the tiling. |
| T-03-SC | Tampering | cargo/npm installs | high | accept | No new packages; the oracle is stdlib Python and the runner uses existing dev-deps. |
</threat_model>
