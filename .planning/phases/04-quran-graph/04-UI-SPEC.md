# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope note (stale-verification refresh): this contract documents the UI surface
> Phase 4 already built — CLI neighbor/path/subgraph/pattern views, Graph JSON
> export, static DOT/SVG render, review-queue and doctor output. It proposes no
> new scope. Interactive explorer / Web GUI / TUI belong to Phase 5 (deferred).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Rust CLI + static file renderers; not a React/Next.js/Vite project — shadcn gate not applicable) |
| Preset | not applicable |
| Component library | none — plain-text CLI renderer (`CommandOutput { human, json }`) + hand-emitted DOT/SVG (`quran_graph_export.rs`; no graphviz binary or render crate per 04-RESEARCH) |
| Icon library | none (text-only CLI; no icon actions) |
| Font | terminal monospace inherited for CLI output; viewer-default sans for SVG (`font-size` only, no `font-family` pinned) |

Focal point per surface (visual hierarchy — summary first, detail indented below,
truncation always inline on the summary line, never hidden): neighbor/path/
subgraph/pattern views → the column-0 count line; review verbs → the
`<verb> <id> (<decision>)` line; doctor → the `GRAPH DOCTOR` header then one
`[STATUS]` line per check; export → the `exported …` line; DOT/SVG files →
the seed node (layer 0) then hop layers, truncation banner last. No icon-only
actions exist (text-only CLI); every status is a word (`yes`, `no path
(complete search)`, `unknown (truncated)`, `pending`), never color or glyph alone.

## Spacing Scale

Declared values (must be multiples of 4). No px rendering exists in this phase;
the px scale is declared reserved-unused so the grid contract stays explicit:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | reserved — unused |
| sm | 8px | reserved — unused |
| md | 16px | reserved — unused |
| lg | 24px | reserved — unused |
| xl | 32px | reserved — unused |
| 2xl | 48px | reserved — unused |
| 3xl | 64px | reserved — unused |

Exceptions: none.

Normative terminal grid (character columns, not px — literal output bytes pinned
by `graph_s1/s2.trycmd` snapshots):

| Rule | Value | Where |
|------|-------|-------|
| Summary line | column 0, single line | every read verb (`neighbors of …`, `reachable …`, `shortest …`, `paths …`, `subgraph of …`, `pattern […] …`, `exported …`, `projection …`) |
| List indent | 2 spaces | quotation lines (`  ayah:1:2 -> quran:…`), ranked path steps (`  1. …`) |
| Remedy indent | 6 spaces | doctor `      remedy: …` / `      next: …` lines |
| Truncation marker | inline ` (truncated)` + `\nincomplete: <reason>` verbatim | every partial result, human output |
| Row rhythm | single-spaced, one finding per line | all CLI human output |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | terminal default (all CLI human output) | regular (400) | 1.0 — single-spaced terminal rows |
| Label | 10px (SVG node IDs, edge predicates) | regular (400) | n/a — absolute SVG coordinates |
| Heading | terminal default, uppercase banner line (`GRAPH DOCTOR`) | regular (400) | 1.0 |
| Display | 13px (SVG truncation banner) | bold (700) | n/a — absolute SVG coordinates |

3 sizes, 2 weights. Arabic text is never typeset by this phase: graph records
carry refs + hashes only; display text resolves through the canonical reader.
SVG root carries `direction="rtl"` so mixed-direction labels order correctly.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | terminal default — zero color codes emitted in CLI output | All CLI surfaces inherit the operator terminal theme |
| Secondary (30%) | `#eef` fill / `#448` stroke (nodes), `#888` (edge lines), `#555` (edge labels) | SVG graph ink |
| Accent (10%) | `#a00` | Truncation banners only |
| Destructive | none — destructive repair is gated by confirmation text, never by color alone | `doctor-repair` verbs |

Accent reserved for: SVG `truncated: <reason>` banner text; DOT `__truncated`
plaintext node + `// truncated: <reason>` comment (same semantic slot in the
monochrome DOT medium). Accent is never applied to interactive elements,
headings, or node/edge ink.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `qai quran graph neighbors --db --node <stable-id>` — open a bounded neighbor view around any verse, word, root, or concept (e.g. `qai quran graph neighbors --db --node ayah:1:1` → `neighbors of ayah:1:1: 8 node(s), 7 edge(s)` + `  ayah:1:2 -> quran:test-edition-min@0.1.0:1:2` pinned-quotation lines) |
| Empty state heading | Zero-count summary line, never a generic "No data" string: `neighbors of <node>: 0 node(s), 0 edge(s)`; `subgraph of N seed(s): 0 node(s), 0 edge(s)`; path views render `no path (complete search)` — only when `truncated == false` |
| Empty state body | Counts are the state — no body copy. Unknown subgraph seeds skip to complete-empty (typed, exit 0). Fresh database with nothing built: doctor reports `Skipped` + the build remedy naming the build command |
| Error state | `[QAI-GRAPH-NNNN] <detail>` + `Remedy: <fix>` + `Next: qai graph … --help` (code + remedy + next command always together, never a bare message). Usage: `specify exactly one of --file or --db`. Format: ``unknown export format `x`; use json, dot, or svg``. Word-root with no dataset: `[QAI-MORPH-0004] …` typed unavailable (never an empty list). Quotation fail-closed: `quotation unavailable for '<stable-id>': …`. Review input: `bad evidence JSON: …`, `reviewer and method must both be non-empty (OD-02)` |
| Destructive confirmation | `qai quran graph doctor-repair <quarantine-dangling \| tombstone-gc \| rebuild-projection>` requires explicit `--yes` or terminal `Type APPROVE to <verb> \`<target>\``; refusal renders `refusing to <verb> without --yes` (non-terminal) or `not approved`. Success renders `<summary> (audit #<seq>)` with before-and-after counts (human) + full records (JSON) |
| Truncation rendering | `… (truncated)` + `incomplete: <reason>` verbatim on the summary line (CLI); `// truncated: <reason>` + `__truncated` node (DOT); `truncated: <reason>` banner (SVG). Partial results are never rendered as absence or as negative claims; truncated path searches render `unknown (truncated)` / `reachable …: unknown (truncated)`, never `no path` |
| Review report line | `<verb> <assertion-id> (<pending \| accepted \| rejected \| superseded \| disputed>) by <reviewer> at <decided-at>[ (reused)]` (e.g. `proposed … (pending) …`, `accepted …`); correct renders `<report> (supersedes <old-id>)`. Suggestions stay labeled pending with algorithm attribution until a recorded human decision |
| Doctor line | `GRAPH DOCTOR` header, then `[<PASS\|WARN\|FAIL\|SKIPPED>] <check-id> — <summary>` + indented `remedy:` / `next:` lines; any Fail exits VALIDATION, otherwise OK |
| Export line | `exported <n> nodes, <m> edges, <k> assertions as Graph JSON (projection <id>)` (stdout) or `exported … to <path> (projection <id>)` (file); envelope marker `quran-graph-json-v1`; only effective assertions for kept edges ship |

| long-text | E5 DOT/SVG | ✅ covered | Stable IDs XML/DOT-escaped, never clipped in the file (viewer handles display width); truncation banner node present when partial |
| long-text | E8 inspect/build | ✅ covered | Manifest fields are short IDs/versions joined with `, `; single line, no wrapping needed |
