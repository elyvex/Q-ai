<objective>
Complete the layer-separation requirement on the translation side. `REQ-data-separation-layers` is mostly satisfied — attribution is mandatory, alignment is validated, and the types keep canonical and translation apart — but the translation content hash is written as an empty string and the declared license is replaced by a synthesized placeholder (QC-08, QC-09 tail, F-7).

Purpose: a translation layer without a content hash cannot be integrity-checked or differenced, and a synthesized license misrepresents the dataset's redistribution terms. Both are small, bounded completions of an already-correct model.

Task ledger: `TASK-002-canonical-quran-core` (see `docs/04-tasks/`) — this plan is one implementation unit of that phase task.

Output: an additive translation hash recipe, real `text_hash` values on imported translations, verbatim declared licenses, and a negative test that proves the type-level separation rather than merely asserting it in prose.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| translation manifest → translation tables | Untrusted translation bytes and declared license cross into non-canonical tables only. |
| translation tables → reader view | Translation text is attached as an attributed sidecar; it must never occupy the canonical field. |
| translation hash recipe → frozen v1 recipes | A new recipe name must not collide with or mutate the frozen recipes that every stored canonical hash depends on. |
