<objective>
Make ADR-0111's published contract true on a real path: today `verify_quotation` has zero production call sites, the map from verdict to hard failure does not exist, and the only HTTP verification path re-verifies a stored hash without enforcing the verdict (QC-07, F-6, Pitfall 4).

Purpose: criterion 5 ("every quotation verifies via `verify_quotation` with mismatch as a hard failure") is a citation-integrity guarantee the whole platform rests on. The plan builds the shared verdict mapping, one production operator surface that exercises it, and enforcement on the existing HTTP answer path — while recording, rather than wrapping, the direct-read paths that cannot mismatch by construction.

Task ledger: `TASK-002-canonical-quran-core` (see `docs/04-tasks/`) — this plan is one implementation unit of that phase task.

Output: a shared verdict→hard-failure mapping, `qai quran verify-quotation` with an exit-code snapshot, HTTP enforcement, and a recorded read-path exemption.
</objective>

**Posture:** ASVS Level 1; any unmitigated `high`-severity threat blocks this plan — no auto-approval.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| externally supplied quotation → verifying surface | Untrusted operator text crosses here; it is compared against canonical bytes and never stored or echoed. |
| persisted citation verdict → HTTP response | A stored verdict is re-served to clients; a failed verdict must not be presented as a successful verification. |
| canonical reader → quotation type | Quoted canonical text may travel only inside the canonical quotation type. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-17 | Repudiation | `verify_quotation` with no production caller | high | mitigate | Add a shared verdict→hard-failure mapping plus a production CLI surface and HTTP enforcement, with a trycmd exit-code assertion proving mismatch is not downgraded. |
| T-02-18 | Spoofing | HTTP returning a failed stored verdict as success | high | mitigate | Apply `require_exact` in `citation_handler`/`api_citation` and return the typed error response; assert with a server test. |
| T-02-19 | Tampering | hash computed from the supplied text rather than the canonical row | high | mitigate | The verifier returns the resolved canonical hash from the reader-backed resolver; a test asserts a tampered quotation yields a hard failure, never a success with a synthesised hash. |
| T-02-20 | Tampering | normalization altering displayed canonical text | medium | mitigate | No normalization rules are applied in this phase; `MatchAfterDeclaredNormalization` is documented unreachable and the returning text is always the canonical row value. |
| T-02-21 | Information disclosure | CLI printing supplied text | low | accept | The supplied text is operator-provided and non-secret; the CLI prints the verdict and the canonical hash, not a stored secret. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package install occurs in this phase (RESEARCH.md § Package Legitimacy Audit). Any future install requires the package-legitimacy gate plus a blocking human checkpoint. |
